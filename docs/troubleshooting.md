# 常见问题与排错

按问题出现的地方分组。排查时最有用的三个工具：

- 命令行版的诊断日志：`DSHR_LOG=debug dshr headless "…"`（写到标准错误）；
- MCP 服务器的状态和日志：`dshr mcp list`；
- 插件的状态和日志：`dshr plugin list`，或“设置 → 扩展”里插件卡片上的“日志”。

## 模型与连接

**提示“未配置 API 密钥”**

在“设置 → 模型”里编辑对应的提供商，填入 API 密钥；或者设置该提供商的环境变量（如 `DEEPSEEK_API_KEY`，见
[模型与提供商](providers.md#内置提供商)）。自定义提供商没有约定的环境变量，只能在设置里填。命令行版读的是同一个钥匙串，
桌面版里保存过的密钥命令行里直接可用。

**提示“系统钥匙串不可用”，或者保存的密钥读不出来**

没有桌面会话的 Linux 服务器、某些容器里没有系统钥匙串。改用环境变量提供密钥：提供商用它们各自的变量，插件密钥用
`DSHR_PLUGIN_SECRET_<ID>_<名字>`，MCP 密钥用 `DSHR_MCP_SECRET_<服务器>_<名字>`（见 [配置参考](configuration.md#环境变量)）。

**请求失败：401 / 403**

密钥错了、过期了，或者填到了别的提供商下面。重新填写；用账号登录的 DeepSeek（`deepseek-oauth`）提示“登录已过期”时重新登录。

**请求失败：404，或者“模型不存在”**

- 模型 ID 写错了，或者这个提供商没有这个模型：编辑提供商，点“获取可用模型”核对。
- 自定义接口的地址写错了。注意两种协议拼接地址的方式不同：
  - Messages 协议请求 `{地址}/v1/messages`，地址**不要**带 `/v1`（如 `https://gateway.example.com`）；
  - OpenAI 协议请求 `{地址}/chat/completions`，地址**通常要**带 `/v1`（如 `https://gateway.example.com/v1`）。

**“获取可用模型”失败**

有些服务不提供模型列表接口，或者路径不标准。直接“添加模型”，手动填模型 ID。

**选了某个思考等级后报错**

部分模型不支持关闭思考，或者不认某些等级。把思考等级改回“默认”（不发送这个参数）。

**接自定义 Messages 网关时报错，提到 `cache_control`**

网关不认提示词缓存的标记。编辑提供商，把“提示词缓存”改成“关闭”（`prompt_cache = "off"`）。

**一直显示“正在重试”**

网络错误、限流（429）、服务端错误（5xx）会自动重试，一次请求最多 4 次，服务端要求等待时最多等 60 秒。持续失败时检查网络、代理，
或者服务商的状态页；随时可以点停止。

**回复很久没有动静**

模型可能在长时间思考。dshr 在两次收到数据之间最多等 300 秒，超时按网络错误重试。思考等级调低可以更快得到回复。

## 对话与审批

**命令行报“标准输入不是终端，无法询问审批”**

在管道、CI 里运行时没法问你。在终端里运行，或者在**可以丢弃的环境**里加 `--yes`。

**Windows 上每条命令都要审批**

这是预期行为：Windows 上没有能限制写入范围的沙箱，“工作区内修改”模式下运行命令都要询问。可以：对常用的命令选“允许，本会话内不再询问此工具”；
改用“自动审查”让模型放行低风险的命令；或者在受控环境里用“完全访问”。

**macOS 上命令报“Operation not permitted”**

“工作区内修改”模式下命令在沙箱里运行，只能写工作区、临时目录和常见的工具缓存（`~/.cargo`、`~/.npm`、`~/.cache` 等）。需要写其他位置的命令
（如往 `~/.gradle` 写缓存）会失败。切到“自动审查”或“手动确认”（这两种模式下命令不进沙箱，按审批执行）。

**agent 说“会话处于只读模式”**

当前是规划模式，或者一个只读的插件预设。在预设菜单里切回“标准模式”。

**对话很长之后变慢、变贵**

上下文到 75% 时会自动压缩。也可以：从合适的一轮“分叉”出新会话；新任务开新会话；在 `[plugins.compaction] threshold` 里调低阈值。
如果看到压缩失败（摘要请求出错），这一轮不会再试，下一轮会重新尝试。

**我在 AGENTS.md 里写的约定没生效**

- 项目的 `AGENTS.md` 必须在**工作区根目录**；子目录里的不会读取。
- 文件要是 UTF-8，单个最多读 32 KB。
- 改动从下一轮起生效。确认“设置 → 扩展 → 内置功能”里“项目说明”没有被关掉。

**Skill 没被用上**

模型只凭 `description` 判断要不要读一个 Skill：把它写成“什么时候用”（用户会怎么说），而不只是“它是什么”。检查 `SKILL.md` 的 front matter 是单行的
`name: …`、`description: …`。同名的 Skill 只保留优先级最高的一个（`.dshr/skills` > `.agents/skills` > `.claude/skills` > 全局）。

## 插件

**插件的状态是“待授权”（命令行：“等待 …”）**

清单里有没允许过的能力，插件不会激活。在插件卡片上点“允许”，或 `dshr plugin grant <id>`。插件更新后多出来的能力同样要再允许。

**状态是“激活失败”**

原因写在状态后面：清单格式错误、语法错误（带行号）、导出不合规、工具名和已有工具冲突、`activate` 抛了异常、版本要求不满足……
用 `dshr plugin dev <id>` 打开调试台，保存后会重新加载并打印完整的报告。

**`dshr plugin list` 显示“没有装上：id 和内置插件重名”**

插件 id 和内置功能的 id 冲突（如 `mcp`、`skills`、`title`），换一个 id。

**状态是“使用旧版本”**

热重载时新版本加载失败，仍在运行旧版本。按卡片上的原因修好后保存即可。

**状态是“已停止”**

插件连续 3 次失控（超时或内存耗尽），本次运行里被停下。修好后保存文件（热重载）或重启即可恢复。

**插件的 `fetch` 报错说主机不允许**

- 主机必须在 `net:` 里声明；重定向的每一跳也要在范围内。
- `net:*`、`net:*.example.com` 不包括 `localhost` 和 IP 地址，本机服务要写 `net:localhost`、`net:127.0.0.1` 这样的具体主机。
- 标了 `readOnly` 的工具、同步钩子、`render`、`prompt` 里不能联网。

**插件写的东西不见了**

插件自己的数据要放在 `host.readData` / `writeData`（`~/.dshr/plugin-data/<id>/`）里。写到工作区的文件只属于那个工作区；没有工作区时
（设置页、后台任务）`readFile` / `writeFile` 指向数据目录。

**创造模式里 agent 想改一个已有的插件，每次都要确认**

这是设计上的保护：已经被授予过能力的插件，改过的代码会立即带着这些能力运行，所以每次写都必须由你确认。可以让 agent 用一个新的 id 创建插件。

## MCP

**状态是“连接失败”**

运行 `dshr mcp list`，看最后几行日志：

- 找不到命令：确认命令在 `PATH` 里（在终端里能直接运行）；
- `npx` 第一次运行要下载包，可能超过 30 秒的连接时限：等它下载完会在后台自动重连，或者先在终端里手动运行一次；
- 提示“密钥 … 没有设置”：用 `dshr mcp secret <服务器> <名字>` 设置（见 [MCP 服务器](mcp.md#密钥)）；
- 提示“环境变量 … 没有设置”：配置里用了 `${env:…}`，在启动 dshr 的环境里设置它。

连续失败 5 次后会停止重连，修好后在设置页点“重连”。

**状态是“需要登录”**

点设置页里的“登录”，或者 `dshr mcp login <服务器>`。授权服务器不支持动态注册客户端时，在配置里写 `oauth.client_id`。

**MCP 工具每次都要审批**

MCP 服务器在 dshr 之外运行、不受沙箱约束，所以它的工具在“工作区内修改”模式下每次都询问。可以选“本会话不再询问此工具”，或者用“自动审查”。

## 桌面版

**再次打开 dshr 时没有新窗口**

dshr 同一时间只运行一个实例，再次启动会把已有的窗口调到前台。窗口关掉时默认隐藏到托盘（macOS 是菜单栏），点托盘图标恢复；
不想这样就在“设置 → 通用设置”里关掉“关闭窗口时隐藏到托盘”。要真正退出，用托盘菜单里的“退出”。

**会话在侧边栏里找不到了**

- 会话按它第一轮所在的工作目录分组，可能在一个折叠起来的分组里，展开即可；会话多时点分组下面的“显示更多”；
- 较早版本创建的、没有记录工作区的会话在“其他会话”下；
- 删除的会话在 `~/.dshr/sessions/.trash/` 里，把文件夹移回 `sessions/` 就能恢复。

**自定义的配色方案没生效**

“配色方案”下面会显示原因：颜色键写错、颜色不是 `#rrggbb`、或者正文和背景的对比度低于 4.5:1。开启高对比度时配色由高对比度决定。

**改的快捷键没生效**

写法不对的快捷键会退回默认值（至少要有一个修饰键）。在“设置 → 通用设置 → 键盘快捷键”里重新录制，或者删除 `~/.dshr/keybindings.json` 恢复默认。

**DeepSeek 账号登录卡住**

登录会在浏览器里打开授权页，最多等 10 分钟。浏览器没有自动打开时检查默认浏览器的设置；关掉登录页后重新点一次登录即可。

## 重置

- 恢复默认设置：备份后删除 `~/.dshr/config.toml`（提供商和插件配置也会一起清空）；
- 恢复默认快捷键：删除 `~/.dshr/keybindings.json`；
- 收回某个插件的全部授权：`dshr plugin revoke <id>`；
- 完全从头开始：设置 `DSHR_HOME` 指向一个新目录，原来的数据目录不受影响。钥匙串里的条目（服务名 `dshr`）需要在系统的凭据管理器里手动删除。
