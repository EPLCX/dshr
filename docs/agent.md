# Agent 的工作方式

这篇解释你发出一条消息之后 dshr 做了什么：模型看到哪些内容、能用哪些工具、什么时候停下，以及预设、子代理、
上下文压缩这些机制如何运作。

## 轮次与步骤

- **一轮（turn）**：从你发出一条消息，到 agent 给出最后的回复。
- **一步（step）**：一轮里的一次模型请求，加上这次回复里发起的全部工具调用。

一轮通常由好几步组成：模型先读文件、搜代码（第 1 步），根据结果修改文件（第 2 步），再跑测试（第 3 步），最后汇报。

```text
你的消息
  └─ 第 1 步：请求模型 → 回复里有 3 个工具调用 → 执行（并行）→ 结果写进日志
  └─ 第 2 步：请求模型（带上第 1 步的结果）→ 1 个工具调用 → 审批 → 执行
  └─ 第 3 步：请求模型 → 只有文字，没有工具调用 → 这一轮结束
```

步数**没有上限**。一轮在以下情况结束：

| 结束原因 | 什么时候 |
|---|---|
| 完成 | 模型的回复里不再有工具调用 |
| 中断 | 你点了停止（`Ctrl+C`），或在等审批时停止 |
| 出错 | 模型请求重试多次后仍失败，或遇到不可重试的错误 |

所有过程都以事件的形式追加到会话日志（`turn/start`、`step/start`、`assistant/message`、`tool/call`、`tool/result`……），
界面和命令行实时显示的就是这些事件。日志格式见 [会话与日志格式](sessions.md)。

## 模型看到什么

每次请求由三部分组成：

1. **系统提示词**：
   - 内置的基础提示词（如何开展任务、如何使用工具、安全守则、如何回复），在会话开始时写进日志；
   - 运行环境：工作区路径（是否 git 仓库）、操作系统和 `run_shell` 用的 shell（Windows 是 `cmd /C`，其他是 `sh -c`）；
   - 全局和项目的 `AGENTS.md`，以及可用 Skills 的目录（见 [项目说明与 Skills](instructions-and-skills.md)）；
   - 插件追加的内容（插件的 `prompt` 导出）；
   - 当前预设的说明（规划、审查等）。

   插件追加的部分每轮开始时算一次，一轮之内保持不变；它们只附加在请求上，不写进日志，所以切换预设、修改 `AGENTS.md`
   从下一轮起生效，不影响历史。
2. **对话**：从会话日志投影出来的消息——你的消息和附件、模型的回复、工具调用与结果、插件写的事件。
   压缩过的部分用摘要代替。
3. **工具定义**：这一步可用的全部工具。只读的一轮（规划模式等）只发送不会修改任何东西的工具。

**日期和权限模式**每轮会变，没有放进系统提示词，而是以一条 `<environment>` 说明的形式追加在对话里，只在和模型
最近看到的那条不同时才追加（第一轮、换了权限模式、过了零点、旧的那条被压缩掉）。这样系统提示词保持不变，
提供商的提示词缓存不会因为切换一次权限就整段失效。

## 内置工具

| 工具 | 访问类型 | 作用 |
|---|---|---|
| `read_file` | 读取 | 读 UTF-8 文本文件，行号从 1 开始；`offset` / `limit` 分段读取，单次输出最多约 3 万字符 |
| `list_dir` | 读取 | 列出目录内容，子目录以 `/` 结尾 |
| `grep` | 读取 | 用正则表达式（Rust regex 语法）搜索文件内容；遵守 `.gitignore`，跳过二进制文件；可按 `glob` 过滤、忽略大小写；默认最多 200 条结果 |
| `glob` | 读取 | 按 glob 模式找文件（如 `src/**/*.rs`），遵守 `.gitignore`，最多 500 条 |
| `write_file` | 写入 | 创建文件或整体替换内容，自动创建父目录 |
| `edit_file` | 写入 | 把文件里一段精确匹配的文字替换成新文字（可 `replace_all`）；结果附带 diff |
| `run_shell` | 执行 | 在工作区目录里运行命令（Windows `cmd /C`，其他 `sh -c`），没有终端和输入；默认 120 秒超时，超时连同子进程一起结束；输出保留开头和结尾，过长的部分截断 |
| `update_plan` | 读取 | 创建或更新分步计划，显示在输入卡片上方的计划面板里 |
| `delegate` | 读取 | 把一项独立的子任务交给子代理（见下文） |

此外还有：

- **MCP 工具**：`mcp__<服务器>__<工具>`，以及服务器提供资源时的 `mcp_list_resources`、`mcp_read_resource`（见 [MCP 服务器](mcp.md)）；
- **插件工具**：JS 插件导出的工具（见 [插件开发指南](plugins.md)）；
- **创造模式的工具**：`plugin_read`、`plugin_write`、`plugin_reload`、`plugin_grant`、`plugin_page`（见下文）。

**访问类型**决定一次调用要不要问你：读取永远直接执行；写入看路径在不在工作区里；执行命令和交给外部程序（MCP、能联网的插件工具）
按权限模式处理。具体规则见 [权限与安全](permissions.md)。

`write_file`、`edit_file` 写盘之前，插件的 `beforeWrite` 钩子可以拒绝或调整内容（例如自动格式化）；调整过时，结果里会注明
是哪个插件改的。

## 工具调用的执行顺序

模型一次回复里可能有多个工具调用。dshr 按顺序把它们分批：

- **连续的只读调用**（读文件、搜索、子代理……）组成一批，同时执行，一批最多 8 个；
- **会改东西的调用**各自单独一批，按顺序执行。

每一批先按顺序逐个把关（需要审批的逐个问你），放行的再一起执行，谁先完成先写结果。模型看到的结果按调用 id 对应，不受完成顺序影响。

## 回复被截断时

如果回复达到了单次输出上限（`max_tokens`），最后一个工具调用的参数多半不完整：dshr 丢掉这个残缺的调用，执行完整的调用，
然后自动请求模型接着做（对话里提示“回复达到单次输出上限，已自动继续”）。连续截断超过 3 次时结束这一轮。

## 失败与重试

模型请求遇到网络错误、限流（429）、服务端错误（5xx）或过载时自动重试，最多尝试 4 次，间隔按服务端的 `Retry-After`
或指数退避。重试期间点停止会立即结束。详见 [模型与提供商](providers.md#网络与重试)。

## 中断

点停止（或命令行里 `Ctrl+C`）后：

- 正在生成的回复只保留已经输出的文字，没完成的思考和工具调用丢弃；
- 正在等审批、正在执行的工具调用记为“已取消”（`Interrupted by user.`），命令连同子进程一起结束；
- 这一轮以“中断”结束。之后可以接着发消息，模型能看到中断前的全部内容。

## 预设

预设决定 agent 这一轮用什么方式工作。预设说明只在请求时追加，不写进日志，所以同一个会话里可以随时切换。

| 预设 | 行为 |
|---|---|
| **标准** | 直接完成任务：调查、修改、验证、汇报 |
| **规划** | 只读。先用读取和搜索工具调查（可以委派子代理并行调查），再给出方案：目标与思路、按顺序的修改步骤（文件、函数）、风险与验证方法。不改文件、不运行命令 |
| **审查** | 审查你指定的范围，没指定时审查未提交的改动（会用一条 `git status --short && git diff HEAD` 之类的命令取改动，可能需要审批）。确认每个问题真实存在后按严重程度列出：`路径:行号`、问题、触发条件、修复建议。不主动改文件 |
| **创造** | 把你描述的功能写成一个插件（见下文） |

规划模式是**强制只读**的：不管权限模式是什么，会改东西的工具都不发给模型，模型硬要调用也会被拒绝。

**插件预设**：插件可以提供更多预设，出现在内置四项后面。插件预设可以是只读的，也可以限定模型只能看到哪些工具
（名单外的工具调用会被拒绝）。写法见 [插件 API 参考](plugin-api.md#presets)。

## 子代理（delegate）

`delegate` 把一项独立的子任务交给子代理：它在自己的上下文里工作，用同样的工具，最后只把一份书面报告交回给主代理。
适合“调查这个模块怎么工作”“在另一个目录里做一处范围明确的修改”这类不需要把细节留在主对话里的事。

- 子代理用同样的模型和权限模式；它的系统提示词是专门的子代理版本（不能提问、最后写报告）。
- 子代理**不能再委派**，避免层层嵌套。
- 子代理继承父代理预设的限制（只读、插件预设的工具名单），但不继承预设的说明——那些说明是写给主代理的。
- 子代理的每一步显示在父会话里这张 `delegate` 卡片的实时输出中，它的审批请求也挂在这张卡片上。
- 子代理的完整日志在父会话目录下：`sessions/<会话 id>/agents/<调用 id>.jsonl`。
- 只读的子代理调用可以和其他只读调用并行执行，所以模型可以一次派出几个子代理分头调查。

有 `agent:run` 能力的插件也可以用 `host.agent.run({ task, preset })` 启动子代理。

## 上下文压缩

对话越长，每次请求带的上下文越多。当上下文用量达到上下文窗口的 75%（`[model] context_window`，默认 128000 token）时，
dshr 在下一步开始前做一次压缩：

1. 找到最近一个完整的边界（一轮或一步的结束处，保证工具调用和结果成对）；
2. 让当前模型把这之前的对话写成摘要：你的要求和约束（最近一次要求逐字引用）、做过什么（决定、改过的文件、跑过的命令和结果）、
   当前状态和下一步、之后还会用到的细节（路径、函数名、代码片段）；
3. 写入一条 `context/compaction` 事件。之后的请求里，边界之前的对话由摘要代替；**原始事件仍完整保留在日志里**。

用量以模型最近一次报告的为准（包括缓存的输入、工具定义和追加的提示词），之后新增的内容按字符估算。摘要请求失败时，
这一轮不再尝试（上下文快满时摘要请求最容易失败，反复重试只会白白多花请求）。

阈值可以调整：

```toml
[plugins.compaction]
threshold = 0.6     # 0.1–1.0，默认 0.75
```

也可以在“设置 → 扩展 → 内置功能”里改，或者把“上下文压缩”整个关掉。插件也能接管压缩（`context:compact` 能力）。

## 会话标题

第一条消息发出后，dshr 在后台根据这条消息生成简短标题（中文不超过 16 个字），写入 `session/title`。回复不等待标题，标题生成失败也不影响对话。
可以随时在侧边栏重命名，自动标题不会覆盖手动设置的标题；也可以在“设置 → 扩展”里关掉“会话标题”。

## 排队与插队

agent 运行时你仍然可以发消息（见 [桌面版使用指南](desktop.md#运行中继续输入排队与插队)）：

- **排队**：等这一轮结束后作为新的一轮发出；
- **插队**：当前这一步结束后、下一次请求模型之前接进对话，模型马上就能看到。如果模型本来已经要结束这一轮，看到插队的消息会接着处理它。

## 创造模式

在预设菜单里选“创造模式”（命令行：`--preset create`），描述你希望 dshr 能做的事——它会把这件事做成一个 **JS 插件**，
而不只是手动做一次。插件可以给模型新的工具，也可以给你新的界面（侧边栏页面、设置页、面板）。

agent 在这个模式下多了五个工具：

| 工具 | 作用 |
|---|---|
| `plugin_read` | 读插件的一个文件；不给路径时列出插件的文件，不给 id 时列出已安装的插件（用来确认 id 没被占用） |
| `plugin_write` | 写插件的一个文件（`plugin.toml`、`index.js` 等） |
| `plugin_reload` | 重新加载插件，报告能否加载、为什么不能（语法错误带行号）、导出了哪些工具、还在等授权的能力、最近的日志，并把每个页面渲染一遍 |
| `plugin_grant` | 请求你允许插件声明的能力 |
| `plugin_page` | 像用户一样操作插件的页面：填输入、执行动作、读重新渲染的结果 |

典型流程：选一个新的插件 id → 写 `plugin.toml` 和 `index.js` → `plugin_reload` 直到加载成功 → 用真实的输入把每个新工具调用一遍 →
如果需要能力，先用通俗的话告诉你每项能力允许什么、为什么需要，再 `plugin_grant` → 最后总结插件做什么、在哪里。

安全上的保证：

- 新插件在你允许它的能力之前什么都碰不到（声明了能力却没被允许的插件根本不激活），所以写新插件的文件不必逐次询问
  （手动确认模式下仍会问）。
- **授予能力必须由你亲自确认**：不受权限模式影响（桌面版的完全访问也会问），不交给自动审查，也不能设为“本会话不再询问”；
  授予的正好是审批卡片上列出的那几项。唯一的例外是命令行的 `--yes`——那是你明确要求全部放行。
- 修改一个**已经被授予过能力**的插件，每次都要你确认，因为改过的代码会立即带着这些能力运行。所以 agent 会为新功能创建新插件，
  而不是改写已安装的插件。链接到插件目录之外的插件（`dshr plugin link`）不能在创造模式里修改。
- `plugin_reload` 和只渲染页面的 `plugin_page` 只会带着你已经允许的能力运行代码；用 `plugin_page` 执行页面动作视同调用外部服务，按权限模式处理。
- 这五个工具只在创造模式下出现，其他模式下调用一律被拒绝。插件写好后留在插件目录里，文件变化时自动热重载。

完整的授权规则见 [权限与安全](permissions.md#创造模式)。

插件的完整写法见 [插件开发指南](plugins.md)。
