# dshr 设计规范

原版 DeepSeek Harness 只作为**信息结构和交互流程**的参照（有哪些页面、每页有哪些内容、操作顺序）。
视觉上不逐像素复刻，统一按本规范实现。规范的唯一实现位置是
[`crates/ui/src/design.rs`](../crates/ui/src/design.rs)：视图代码只使用其中的 token 和基础组件，
不直接写颜色值、圆角或零散的字号。

## 1. 原则

1. **内容优先，界面安静。** 对话内容和用户输入是主角；装饰、边框、阴影能省则省。
2. **只有一个强调色。** 品牌蓝只用于：主要的行动点（发送）、选中状态的强调、链接和品牌标记。
   普通的“主要按钮”用前景色（浅色模式下为近黑），不与强调色抢注意力。
3. **层级靠字号、字重和颜色区分，而不是靠边框。** 同一层级的元素在全应用里长得一样。
4. **一套阶梯，处处复用。** 间距、圆角、字号、控件高度都从固定阶梯里取值，不发明新数值。
5. **深浅色共用语义 token。** 视图只引用“次要文字”“下沉表面”这类角色，不引用具体颜色。
6. **每个可交互元素都有完整状态：** 默认、悬停、按下、禁用、聚焦。禁用态必须看得出来，且不能响应点击。

## 2. Token

### 2.1 间距（4px 基准）

| Token | 值 | 用途 |
|---|---|---|
| `XS` | 4 | 图标与文字之间、紧密排列的小元素 |
| `S` | 8 | 控件内部、同一组内的相邻元素、标签与控件之间 |
| `M` | 12 | 列表项内边距、卡片内的元素间距 |
| `L` | 16 | 卡片内边距、消息之间 |
| `XL` | 20 | 表单项之间、面板内边距 |
| `XXL` | 24 | 页面边距、弹窗内边距 |
| `XXXL` | 32 | 区块之间 |

### 2.2 圆角

| Token | 值 | 用途 |
|---|---|---|
| `SM` | 6 | 小按钮、标签、紧凑控件 |
| `MD` | 8 | 按钮、输入框、列表项、导航项 |
| `LG` | 12 | 卡片、菜单、工具调用卡片 |
| `XL` | 16 | 面板（下沉的表单容器）、消息气泡 |
| `XXL` | 24 | 输入卡片（Composer）、弹窗 |
| `FULL` | — | 圆形按钮、状态点、徽标 |

嵌套时内层圆角 ≤ 外层圆角。

### 2.3 字体

| 样式 | 字号 / 行高 | 字重 | 用途 |
|---|---|---|---|
| `display` | 28 / 36 | 400 | 首页标语、欢迎窗标题。中文大字号用常规字重，层级靠字号拉开 |
| `title` | 20 / 28 | 600 | 弹窗、窗口标题 |
| `heading` | 16 / 24 | 600 | 区块标题、卡片标题 |
| `label` | 14 / 20 | 500 | 表单标签、导航项、列表项 |
| `body` | 14 / 22 | 400 | 默认界面文字、说明 |
| `content` | 15 / 24 | 400 | 对话内容（用户消息、模型回复） |
| `caption` | 12 / 18 | 400 | 提示、辅助信息、分组标题 |
| `mono` | 13 / 20 | 400 | 工具参数、命令输出、代码 |

中文界面使用全角标点；按钮文字不加句号；提示语是完整的句子。

### 2.4 颜色角色

视图只使用下列角色。中性色取自 gpui-component 主题，随深浅色自动切换；强调色由本规范定义。

| 角色 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `text.primary` | 主题 foreground | 同左 | 正文、标题 |
| `text.secondary` | 主题 muted_foreground | 同左 | 说明、提示、分组标题 |
| `surface.base` | 主题 background | 同左 | 窗口主体、卡片 |
| `surface.raised` | 主题 background | 主题 popover（比页面略亮） | 弹窗、菜单等浮在页面之上的表面 |
| `surface.sidebar` | 主题 sidebar | 同左 | 侧边栏 |
| `surface.sunken` | 主题 muted（60% 不透明度） | 同左 | 面板、分段控件底色、工具输出 |
| `surface.selected` | 主题 secondary | 同左 | 选中的导航项、列表项、用户消息气泡 |
| `border.subtle` | 主题 border | 同左 | 卡片描边、分隔线 |
| `accent` | `#4D6BFE` | `#7088FF` | 发送按钮、品牌标记、强调 |
| `accent.soft` | accent 12% | accent 20% | 徽标底色、强调色的浅底 |
| `status.success` | 主题 success | 同左 | 完成、已就绪 |
| `status.warning` | `#B45309` | `#F59E0B` | 需要注意的配置提示（文字可读） |
| `status.danger` | 主题 danger | 同左 | 错误、失败、破坏性操作 |
| `scrim` | 黑色 35% | 黑色 55% | 弹窗遮罩 |

### 2.5 尺寸与层级

- 控件高度：`sm` 28、`md` 36、`lg` 40。行内按钮用 `sm`，表单与主要操作用 `md`。
- 图标：14（与 caption 同行）、16（默认）、20（导航、品牌标记）、32（首页标记）。
- 层级：
  - 0：平铺，用描边或底色区分；
  - 1：输入卡片、下拉菜单，使用中等阴影；
  - 2：弹窗，使用大阴影，并加遮罩。
- 布局常量：侧边栏宽 260，收起后 56；对话内容最大宽 860；弹窗 1000×820（最大占窗口 94%×92%），导航宽 240，内容最大宽 720。

## 3. 基础组件

| 组件 | 规则 |
|---|---|
| **按钮** | `primary`（前景色底，用于“保存”等确认操作）、`outline`（次要操作）、`ghost`（工具栏、列表内操作）、`danger`（只用于破坏性操作的确认）。一组按钮中最多一个 `primary`，放在最右。 |
| **圆形发送按钮** | 36×36，`accent` 底，白色向上箭头；不可发送时降为 35% 不透明度且不响应点击；运行中且输入为空时变为前景色底的停止按钮。 |
| **分段控件** | 用于 2–4 个互斥选项（设置标签页、主题、协议）。按内容宽度显示，不随父容器拉伸。`surface.sunken` 底、圆角 `MD`、内边距 4；选中项为 `surface.base` 底 + 小阴影 + `label` 字重。 |
| **表单项** | 标签（`label`）→ 控件 → 可选提示（`caption`，按语气着色）。标签与控件间距 `S`，表单项之间 `XL`。 |
| **提示** | 中性用 `text.secondary`，成功 `status.success`，需要注意 `status.warning`，错误 `status.danger`。不用背景色块，除非是需要用户立刻处理的错误。 |
| **卡片** | `surface.base` 底、`border.subtle` 描边、圆角 `LG`、内边距 `L`/`XL`。卡片标题用 `heading`。 |
| **面板** | 用于成组的编辑区（如提供商表单）。`surface.sunken` 底、无描边、圆角 `XL`、内边距 `XL`。 |
| **列表项 / 导航项** | 高 32（导航项 40）、圆角 `MD`、左右内边距 `M`；可带 16 图标，图标与文字间距 `S`；悬停与选中用 `surface.selected`，选中项文字用 `label` 字重。 |
| **状态点** | 8×8 圆点：`status.success` 表示可用，`text.secondary` 表示未配置。旁边配文字说明，不单靠颜色表达。 |
| **徽标** | 圆角 `FULL`、`caption`、`accent.soft` 底 + `accent` 字。 |
| **弹窗** | 遮罩 `scrim`；`surface.raised` 底 + `border.subtle` 描边（深色模式下靠它与页面分开）；圆角 `XXL`；顶栏放标题（`title`）和右侧操作（打开配置文件、关闭），顶栏下方是左导航 + 右内容，两侧顶部对齐。 |
| **输入卡片** | 圆角 `XXL`、层级 1、内边距 `M`；文本框无边框；底部一行：左侧依次是附件按钮（+）、预设菜单、权限菜单，右侧为模型菜单与发送按钮。 |
| **消息** | 用户消息：右对齐气泡，`surface.selected` 底、圆角 `XL`、`content` 字号。模型回复：无气泡，Markdown 渲染，`content` 字号。思考过程：左侧细线、`text.secondary`、`body` 字号。 |
| **工具卡片** | 圆角 `LG`、描边；头部一行：状态点、工具名（`label`）、参数（`mono` + 截断）、状态文字（`caption`，按状态着色）。审批区和输出区用分隔线隔开。 |

## 4. 页面结构

- **窗口框架**（自绘标题栏的 Windows、macOS）：侧边栏和标题栏铺同一个 `surface.sidebar` 色，连成一块框架；
  对话区是嵌在框架里的面板：`surface.base` 底、左上圆角 `XL`、上边和左边各一条 `border.subtle` 描边，侧边栏不再有右侧描边。
  框架和内容靠面板的描边和圆角分开，标题栏不是一条孤立的空白。Linux 用系统标题栏，没有框架。
  GPUI 不按圆角裁剪子元素：面板里贴着左上角画底色的东西（如顶边的渐隐）要用 `title_bar::panel_inner_radius()`
  做同样的圆角，否则方角会盖掉面板圆角外面的框架色；对话视图的根元素也因此不设底色，底色由面板画。
- **标题栏**：高 40，和侧边栏的品牌行对齐，整条都能拖动窗口。左边是当前位置：工作区（文件夹图标 + 名字，次要色）›
  会话标题（`body` 字号、中等字重，放不下截断），运行中后面带加载圈，等待处理带提醒图标（和侧边栏一致）；右边是窗口按钮
  （宽 46，悬停底色有过渡，关闭为系统红）。窗口不在前台时整条变淡。系统的窗口标题同步为“会话标题 - dshr”（任务栏、
  Alt+Tab、读屏软件读的是它）。
- **侧边栏**：品牌行（标记 + “dshr”，右侧是“收起侧边栏”图标按钮）→“新会话”（列表项样式，带加号图标）→“搜索对话”（同样式，放大镜图标）→“工作区”标题（右侧是“添加工作区”按钮）与按工作区分组的会话列表
  （没有工作区的会话归在“其他会话”）→ 底部是插件加的入口、“设置”（列表项样式）与状态行（账号状态等，状态点 + caption）。
  收起后宽 56，只剩一列居中的 ghost 图标按钮（都带 tooltip 和无障碍名字）：品牌标记 → 展开 → 新会话 → 添加工作区 → 搜索，
  底部分隔线下是插件入口和设置；会话列表和状态行不显示。宽度在两者之间过渡（`FAST`），内容按目标宽度排版、外层裁切，不跟着挤压换行。
  macOS 自绘标题栏时品牌标记让给红黄绿按钮，标题栏的标题相应右移。
- **首页（空会话）**：品牌标记 + 标语（`display`）+“预览版”徽标，下方是工作区选择和输入卡片，整体在可用区域中偏上居中。
- **对话页**：消息列表居中（最大宽 860），输入区固定在底部，与首页使用同一个输入卡片。
- **搜索对话**：命令面板样式的弹窗，宽 640，靠上居中（距顶 8%），带遮罩，点遮罩关闭。顶部是放大镜 + 无边框大号输入框 + 关闭按钮，
  分隔线下是结果列表：分组标题（`caption`，次要色，“最近”或“结果（N）”），每项是 → 箭头 + 标题（`body`，命中处强调色加粗）
  + 一行 `caption`（工作区 · 相对时间）；高亮项铺 `selected` 底色、箭头变强调色，鼠标悬停即高亮。底部是一条 `surface.sidebar`
  底色的按键提示（键帽 + 说明：↑ ↓ 选择、Enter 打开、Esc 关闭）。读屏：弹窗 `Dialog`，输入框 `SearchInput`（不要用没有展开状态的 `ComboBox`，讲述人不把它当编辑框），焦点等弹窗画出来再进输入框，列表 `ListBox`，
  各项 `ListBoxOption` + 已选择；输入时播报结果个数。
- **设置**：弹窗。左侧导航依次是“通用设置”“辅助功能”“模型”“扩展”、插件加的设置页，最后是“关于”；右侧内容由区块组成，每个区块是“标题（`heading`）+ 说明（`body`，次要色）+ 内容”。

## 5. 辅助功能

### 5.1 键盘

- 所有可点击的东西都用 `design::pressable`（包着 gpui-kit 的 `Button`），不要给 `div` 挂 `on_click`。它自带 Tab 顺序和 Enter/Space 触发，键盘聚焦时显示 2px `focus_ring`（等于 `accent`），鼠标点击时不显示。
- 设置里的“高可见性控件轮廓”：键盘、鼠标聚焦都显示焦点框，外面隔 7px 空隙再画一圈 3px 正文色的外轮廓（`design::focus_outline`），
  外轮廓四周再有一圈淡淡的阴影（几圈越来越淡的细线，不用实心的投影），底下是什么颜色两圈都分得开。外轮廓是只有描边的框，**不要用投影画**：GPUI 的投影是实心的，控件没有底色时会整块涂黑。
  外轮廓画在延后绘制层（`OutlineLayer`，次序 150：比所有弹出层高、比工具提示低），不会被卡片、列表裁掉，
  菜单里有焦点的项的外轮廓也画在菜单上面；只限制在控件所在的可见区域往外扩出外圈的范围内。
  `pressable` 已经内置；自己画焦点框的元素（会话消息、下拉框）用 `design::with_focus_ring`。开关用 `design::switch`
  （基于 `pressable`，带外圈，能设说明；切换时圆钮滑过去、轨道变色，`BASE` + 标准曲线），不用组件库的 `Switch`。
  组件库的按钮、输入框外面套 `design::framed(和 Button::new 一样的 id, 按钮)` / `framed_handle(输入框的焦点句柄, 输入框)`，
  聚焦时画同样的外圈（组件库自己只画一圈半透明的焦点框，高可见性时 `sync_theme` 把它换成正文色）。
  弹出菜单的触发按钮用 `design::framed_trigger`：它把 `Selectable` 转给里面的按钮，可以直接交给 `menu_popover`。
- 只有图标、没有文字的按钮必须设置 `accessibility_label`（`tooltip` 只是补充说明，不算名字）。
- `pressable(...).selected(..)` 只改样式，读屏软件读不到。选中 / 勾选状态要另外给：分段控件用 `role(RadioButton)` + `aria_toggled`（`segmented` 已内置）；单选菜单项用 `design::menu_choice`；设置导航是 `Tab` + `aria_selected`（`nav_item` 已内置，外层 `TabList`）；当前会话是 `ListItem` + `aria_selected`。可展开的标题按钮设 `aria_expanded`。
- 焦点不能丢：窗口打开时聚焦第一个输入框（工作区是输入框，欢迎窗是 API Key）；弹窗打开时把焦点移进弹窗，并用 `focus_trap` 把 Tab 限制在弹窗内；弹窗关闭后焦点回到输入框。
- Esc 关闭弹窗、菜单，或放弃正在进行的编辑（如重命名）。
- 可滚动的页面（设置）里，焦点进到哪一块就把哪一块滚进视口：每个可聚焦的控件（或一小组控件）外面包一层
  `reveal::reveal`，不要只包一整张很高的卡片——比视口还高的块只能对齐它的顶端，里面靠下的控件会落在视口外。
  `reveal` 在绘制这一帧时改滚动位置，要等这一帧画完再重画（`window.defer` 里 `refresh`），否则要等下一次按键才显示出来。
- 窗口最先的两个 Tab 停靠点是“跳到对话内容”“跳到输入框”（`tab_index(-1)`，平时在窗口外面，键盘走到时才显示），
  不用先走过侧边栏里一长串会话。
- 消息列表是虚拟化的，只有画出来的行在系统的 Tab 顺序里。列表里的 Tab / Shift+Tab 由 `ConversationView::on_transcript_tab`
  接管：下一个控件还没画出来时先把那一行滚出来，画好再走进去，整段对话都能用 Tab 走完，不必把所有行都画出来。
  焦点走到的那一行要不要滚，等它这一帧画完、按这一帧的位置判断（`request_reveal`，规则见 `row_is_revealed`）：
  放得下的行整行进视口；比视口高的长回复至少露出一行列表项高（只露出底边一小条不算）；行里的控件（都在行的顶部）要露出行的顶边。
  “跳到最新消息”按下后焦点落在最后一条消息上（按钮有焦点时一直画着，焦点不会随它消失）。
- 弹出菜单（`menu_popover`）打开时焦点落在当前选中的那一项——等菜单画出来之后才落过去。组件库的 `Popover` 在按下
  的同一个事件里就移焦点，那时菜单项还不在无障碍树里，讲述人会把焦点报成窗口、再读一遍窗口标题；所以触发按钮用
  `design::menu_trigger_focus(菜单 id)` 作焦点句柄（`Button::track_focus` + `framed_trigger_with`），打开的那一刻焦点留在它上面。
  菜单里 ↑ / ↓ / Home / End 在各项之间移动，Enter / 空格选中。
  和系统菜单、组合框一样，鼠标移到哪一项焦点就到哪一项（读屏软件随之读出）：菜单项加 `Pressable::focus_on_hover`，下拉框已内置。
  每一项用 `body` 拿到的 `MenuFocus::item(序号)` 作焦点句柄（`Pressable::track_focus`）；在可滚动列表里的项再用
  `MenuFocus::scrolls_in` 登记，焦点移过去时滚进视口。二级菜单：打开它的项用 `on_forward` 登记（→ 打开），
  二级页用 `on_back` 登记（← / Esc 回到上一级，焦点回到打开它的那一项）。
- 全局快捷键在 `lib.rs` 的 `bind_keys` 注册，并同步更新 `SHORTCUTS`（设置页会列出它们）。`KeyBinding` 不认 `secondary-`，按平台写 `cmd-` / `ctrl-`。
- 悬停才出现的操作（如会话的“…”），在该项选中或菜单打开时也要可见，键盘用户才能找到它。隐藏时用 `opacity(0.)`，不要用 `invisible()`：不可见的元素不参与绘制，里面的按钮不在 Tab 顺序里；再用 `in_focus` 在键盘焦点进来时显示出来。

### 5.2 触屏

- 最近一次输入来自触摸屏时是触屏模式（`design::touch_mode`）；用鼠标、键盘就恢复。
  窗口根视图的 `render` 开头调用 `design::update_touch_mode`，输入方式一变 GPUI 会整窗重画。
- 不要只靠悬停：悬停才出现的东西在触屏模式下直接显示；`hover_fill` 在触屏模式下不亮（点过的地方不会一直高亮）。
- 右键菜单同时接长按：用 `on_aux_click` 并检查 `ClickEvent::is_secondary()`（右键、长按都是）。
- Windows 上的触摸由 `touch.rs` 交给 GPUI 的手势识别：轻点是点击，拖动是带惯性的滚动，长按是次要点击或工具提示。

### 5.3 屏幕阅读器

- 直接作为子元素的字符串（`.child(String)`）不进入无障碍树，读屏软件读不到。需要被读到的文字用 `design::readable`（以文字本身作 id）或 `readable_with_id`（列表、逐行输出等可能出现相同文字的地方）。`hint`、`description`、`field`、`badge` 已经内置。
- 页面与区块标题用 `design::heading(text, level)`，读屏软件可以按标题跳转：页面标题 1 级，区块 2 级，卡片 3 级。
- 只靠图标或样式表达的信息（计划步骤的状态、Markdown 回复）在外层用 `.role(Role::Label).aria_value(...)` 给出完整的文字版。
- 点在会话消息的任何地方都让它获得焦点（读屏软件读出全文）：回复正文是可选择文字的 Markdown，会把按下事件和焦点拿走，
  消息在捕获阶段登记、等事件处理完再把焦点拿回来。选了一段文字时 Ctrl+C 复制选中的部分，没选时复制整条消息。
- 不要在播报的同时移动焦点：讲述人读焦点会打断实时区域。用鼠标点发送时焦点留在输入框；首页和对话页里输入卡片外面那一层
  用同一个 id，换页时输入框的无障碍节点不变；“正在回复”稍等一下再播报（`announce_after`）。
- `aria_position_in_set` 从 0 数：AccessKit 的位置是从 0 开始的，各平台的适配层读给读屏软件时再加 1。
  先加了 1 的话第一项会读成“项 2”。
- 输入框、下拉框必须有名字：`Input::aria_label`、`Select::accessibility_label`，与旁边的标签文字一致。
- 名字要短、重点在前。设置行里的控件，名字就是这一行的标题，不带页名；这一行的说明设在控件上（`aria_description`，
  下拉框用 `DropdownState::set_description`），讲述人读作“减少动态效果，跟随系统，组合框，已折叠，减少应用中的动态效果……”。
  只有同一页里会重名的表单项（如 MCP、提供商表单里的“名称”）才用 `in_section` 带上区块（读作“名称，MCP 服务器”）。
  说明、快捷键、完整路径、工具参数这类补充放进 `aria_description`（读屏软件停一下才读，可以打断），不要拼进名字。
- 焦点要给已经画出来的东西：刚展开的列表、刚出现的消息，等它画出来再给焦点（`design::focus_after_paint`），否则无障碍树里
  还没有这个节点，讲述人收不到这次焦点变化（下拉框以前第一项读不出来、菜单打开时读一遍窗口标题都是这个原因）。
  不要在打开浮层的事件处理里直接给浮层里的东西焦点。从首页发出第一条消息后，焦点落在这句话上。设置行、表单项不再设成
  带名字和描述的分组：控件名里已经有标题，分组再报一遍，讲述人每到一个控件都要先听一遍分组名和整段说明。
- 一组重复的按钮（如每个提供商的“编辑”）用 `accessibility_label` 带上对象名。
- 弹窗根节点设 `role(Role::Dialog)` 和 `aria_label`。GPUI 目前没有“隐藏背景”的属性，背景内容仍在无障碍树里，靠焦点陷阱把键盘留在弹窗内。
- 可用 `.dev/uia.ps1` 的 `Show-DshrTree` 查看程序当前暴露给读屏软件的内容（`.dev/` 是本地调试目录，不进版本库）。

### 5.4 辅助功能设置

设置里单独一页“辅助功能”：

- **高对比度**只在这里开关，不出现在“配色方案”的列表里（以前选过它的，启动时改成“开启高对比度 + 默认配色”）。
- **高对比度**、**文字大小**默认都是“跟随系统”（文字大小：Windows 的“文本大小”，其他平台当作 100%；
  超出 90%–130% 的按两头算）。系统设置在窗口外观变化、回到前台时重新读（`system_a11y`）。
- **高对比度**：关闭 / 开启 / 跟随系统（Windows 的“对比度主题”、macOS 的“增强对比度”；窗口外观变化、回到前台时重新读）。
  生效时用内置的高对比度配色（`backend::builtin_high_contrast_theme`，按 WCAG AAA：文字在每种底色上 ≥ 7:1，描边、焦点框 ≥ 3:1，
  测试 `high_contrast_meets_aaa` 逐对检查），配色方案下拉框变淡、不能改，说明里写明原因。
  用了任何配色方案（包括高对比度）时，`sync_theme` 也把它套到组件库的主题上（`apply_palette_to_theme`），输入框、组件库按钮、
  滚动条和我们自己画的用同一套颜色。
- **文字大小**：90% / 100% / 115% / 130%。`Typography` 的字号、行高乘这个比例；组件库的字号和窗口的 rem 由 `sync_theme`
  同步。列表项、导航项用最小高度而不是固定高度，字变大时行跟着变高。新写的文字样式一律走 `Typography`，不要直接写 `text_size`。
- **高可见性控件轮廓**、**减少动态效果**：从“通用设置”移过来。

### 5.4.1 图标

`gpui_kit::assets::Assets` 只内置组件库自己用的图标。用了默认集合以外的 Lucide 图标（`gpui_kit::assets::IconName::…`），
把它加到 `crates/ui/src/assets.rs` 的 `icon_assets!` 列表里，否则画出来是空的。
Lucide 里没有的图标（如“辅助功能”页的通用无障碍标志）按 Lucide 的风格画成 SVG，放进 `assets.rs`，
在 `design::AppIcon` 里加一项，用法和 `IconName` 一样。

### 5.5 动效

实现在 [`crates/ui/src/design/motion.rs`](../crates/ui/src/design/motion.rs)，视图只用其中的常量和函数，不自己写时长、缓动和位移。

**基调：有方向、有层次，但不抢内容。** 东西从它“来的那一边”出现，浮层到位前轻轻越过一点再回来，
退场比进场短、只往回退一半距离。动效只是提示，任何信息都不能只靠动效表达，状态变化同时要有文字或图标。

| Token | 值 | 用途 |
|---|---|---|
| `FAST` | 140ms | 悬停、选中、小块提示的淡入，以及所有退场 |
| `BASE` | 220ms | 菜单、下拉框、列表行进场、展开与折叠 |
| `SLOW` | 320ms | 弹窗、首页标题、欢迎窗 |
| `NUDGE` / `SHORT` / `PAGE` / `MEDIUM` | 4 / 8 / 12 / 16px | 提示 / 行与菜单 / 页面切换 / 弹窗 |
| `enter` | cubic-bezier(0.16, 1, 0.3, 1) | 进场：很快到位，最后一段放缓 |
| `exit` | cubic-bezier(0.4, 0, 1, 1) | 退场：先慢后快，干脆地离开 |
| `standard` | cubic-bezier(0.2, 0, 0, 1) | 状态变化：底色、高度、箭头旋转 |
| `overshoot` | ease-out-back（约 7% 过冲） | 只用于浮层（弹窗、菜单、下拉框）的位移；不透明度永远在 0–1 之内 |
| 错峰 | 菜单项 15ms、侧边栏首次载入 20ms、首页 60ms；最多排到第 8 个 | 一组同时出现的东西依次出现 |

各处怎么动：

| 位置 | 进场 | 退场 |
|---|---|---|
| 弹窗（设置、插件页面） | 遮罩淡入；卡片从下方 `MEDIUM` 带过冲浮上来（`SLOW`），阴影随之渐显；设置的内容比卡片晚一步浮上来 | 卡片下沉一半距离并淡出（`FAST`），遮罩随之淡出；焦点立刻回到输入框 |
| 菜单（权限、预设、模型、会话的“…”） | 从触发按钮那一侧带过冲滑出（`BASE`），选项错峰移入 | 原处画一个不响应操作的残影，退回触发按钮那一侧并淡出 |
| 下拉框 | 同菜单，方向跟列表展开的方向 | 同菜单 |
| 页面切换 | 设置导航：往下切新页从下面来，往上切从上面来；提供商表单的“添加方式”：往后从右边来，往前从左边来 | — |
| 切换会话 | 对话区淡入并上浮 `SHORT` | — |
| 消息列表的新行 | 自己发的消息从右边滑入，其余的从下面浮上来 | — |
| 展开、折叠（工具输出、审批区、实时输出、MCP 与提供商表单、自定义设置、插件面板、侧边栏分组） | 高度展开（`BASE`），内容同时淡入；展开箭头转向 | 高度收起（`FAST`）后再移除 |
| 悬停、选中（列表项、导航项、工具卡片标题、菜单项、下拉选项） | 底色过渡（`FAST`），画在控件最底层的 `Highlight` | 同左 |
| 发送按钮 | 可用与不可用之间不透明度过渡；发送与停止之间底色交叉淡入，新图标轻轻浮上来 | — |
| 提示、保存结果 | 淡入并上浮 `NUDGE` | 立即消失 |
| 错误 | 淡入，再左右轻晃两下（`NUDGE`，越晃越小），原因写在文字里 | 立即消失 |
| 首页、欢迎窗 | 品牌标记、标语、徽标依次浮上来，输入卡片随后 | — |
| 标题栏 | 换会话、标题变了时当前位置轻轻浮上来；窗口切到后台、回到前台时整条渐淡、渐亮 | — |
| 对话面板顶边 | 往下看过、内容从顶边滚出去时，顶上出现一段渐隐（停在最上面时没有） | 滚回最上面时淡出 |
| 运行中 | 侧边栏会话、标题栏、计划步骤的加载圈转动 | — |
| 等待回复 | 还没有文字时三个点依次亮起（读屏软件读“正在回复”） | — |

规则：

- **选对做法。** 出现即挂载的内容用 `Entrance`（`fade_in` / `nudge_in` / `rise_in` / `slide_in` / `error_in`），
  动画状态记在元素上。要退场的用 `presence`：关上后它还会返回一小段“退场中”，调用方这期间继续画（不响应操作），
  返回 `None` 才移除；中途反悔从当前位置往回走。浮层用 `pop` 画出中间状态，高度用 `reveal` / `expand`。
  虚拟列表（消息列表）里的行滚出视口再滚回来，元素状态已经没了，用 `Timeline` 按登记的时刻算进度，不会重播；
  行高变化的动画播放期间要每帧对那一行 `remeasure_items`（列表缓存了行高）。
- **包裹层的 id 要稳定。** 需要重播时换一个 id；不要用会变的 id 包裹可能持有键盘焦点的控件，id 一变焦点就丢了。
  GPUI 按 id 记着一个动画播到第几段，所以 `motion` 里的一次性动画统一是“停一下 + 播放”两段：同一个 id 前后可以换延迟、
  换进场方式（比如侧边栏只在刚载入时错峰），但不要自己直接调 `with_animation(s)`，也不要和循环动画共用 id，
  段数一变 GPUI 会越界崩溃。
  `reveal` 完全展开时保持同样的元素结构，里面控件的状态不会在动画结束时丢掉。
- **弹出菜单用 `design::menu_popover`。** 打开、关闭、焦点和点外面关闭交给组件库的 `Popover`，外观和动画由它画。
  不要让 `Popover` 为了退场多开一会儿：它重新打开会把焦点抢回菜单，读屏软件会再报一次。
- **带阴影的浮层不要直接整体淡入。** GPUI 没有图层合成，`opacity` 按每个图元分别相乘，阴影会先于卡片显出来、
  像一块暗板透过卡片。用 `pop`（阴影按不透明度的三次方渐显），浮层的阴影取 `design::shadow`。
- **悬停底色用 `Highlight` / `design::hover_fill`，不用 `.hover(|s| s.bg(..))`。** 控件本身不再设 `bg`，
  `Highlight` 作为第一个子元素铺满控件（`pressable` 有 2px 透明焦点框，`hover_fill` 已经算进去）。
- **GPUI 只能变换 SVG 和图片。** 缩放、旋转只用在图标上（展开箭头 `turn`、加载圈 `spinner`），不能缩放整块内容。
- **循环动画只用于状态提示**（加载圈、等待回复的点），帧率限 30；不做闪烁、视差和装饰性的循环动画。
  停在起始帧时的样子必须本身就能读懂（静止的图标、三个一样淡的点，旁边的文字照常说明状态）。
- **减少动态效果时没有动画。** 元素直接以最终状态出现、消失，循环动画停在起始帧。
  “减少动态效果”默认跟随系统，可在设置 → 通用里改为“减少”或“完整”。上面所有做法都已经遵守它，自己调
  `request_animation_frame` 驱动动画时要先检查 `cx.reduce_motion()`。
- 动画播完就不再请求帧；不要为了动画让缓存的视图（侧边栏、对话区）一直重绘。

### 5.6 颜色与文字

- 不只靠颜色表达状态：状态点旁边写文字，错误提示用 `status.danger` 的同时写清原因。
- 次要文字（`text.secondary`）只用于说明，不承载必须读到的信息。
- 长文案先保住能区分选项的那一部分。“提供商 · 模型”这类名字不要拼成一串再截断（几项会截成一模一样）：下拉框用
  `DropdownState::set_grouped_items`，提供商是组名、选项只写模型名；列表随最长的选项变宽（不超过 520 和窗口），
  触发框里放不下时先截组名。读屏软件照样读完整的“组名 · 选项名”。

### 5.7 性能

- 界面线程上不扫文件、不执行插件脚本、不联网、不读钥匙串。这些放到 `background_executor`，界面先按用户的操作更新
  （开关马上滑过去），做完再对账；失败时退回去并写明原因。例：设置里的插件开关（`SettingsView::toggle_plugin`）。
- 只做这一次操作需要的事：开关一个插件只重载这一个插件（`JsPlugins::set_enabled`），不为它把整个插件目录重新指纹一遍。

## 6. 检查清单

提交界面改动前逐项确认：

- [ ] 没有直接写颜色、圆角、字号，全部来自 `design.rs`；
- [ ] 间距都在阶梯内；
- [ ] 浅色、深色下都截图看过；
- [ ] 中文、英文下都看过，长文案不溢出（截断或换行）；
- [ ] 禁用状态看得出来且不响应点击；
- [ ] 每屏最多一个 `primary` 按钮，强调色只用在约定的位置；
- [ ] 只用键盘（Tab、Shift+Tab、Enter、Space、Esc）能走完新增的流程，焦点环清楚可见；菜单里方向键能用；
- [ ] 触屏模式下没有只能悬停才找得到的操作；
- [ ] 纯图标按钮有 `accessibility_label`，输入框、下拉框有名字；
- [ ] 新增的正文、提示、标题用 `readable` / `heading`，`Show-DshrTree` 里能看到；
- [ ] 新增的动画走 `design::motion`，时长、位移、缓动取自 token，方向和“从哪来、退回哪”一致；
- [ ] 会关上的浮层、会折叠的内容有退场（`presence`），退场期间不响应操作，关上后焦点去了该去的地方；
- [ ] 悬停底色用 `Highlight`，带阴影的浮层用 `pop`，不直接整体淡入；
- [ ] 在“减少动态效果”下没有动画，循环动画停下时状态仍然看得懂；
- [ ] 长名字（带提供商前缀、德文译文）在最窄的宽度下几项仍然分得清；
- [ ] 打开浮层、展开列表时焦点等它画出来再进去（讲述人不读窗口标题）；
- [ ] 点按钮、拨开关后的耗时工作不在界面线程上（插件多时开关不卡）。
